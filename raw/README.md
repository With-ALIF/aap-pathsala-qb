# raw/database-dump-raw-full — ভাগ করা JSONL ডাম্প

## ১. JSONL কী এবং প্রতিটি রেকর্ডে কী আছে

JSONL (JSON Lines) মানে এমন একটি টেক্সট ফাইল যেখানে **প্রতি লাইনে একটি আলাদা আলাদা JSON অবজেক্ট** থাকে, এবং প্রতিটি অবজেক্টের শেষে একটি লাইন ব্রেক (`\n`)। এটি একটি সাধারণ "structured text" ফরম্যাট — যেকোনো লাইন আলাদা করে পড়া যায়, কিন্তু পুরো ফাইলটাও একটি বড় JSON অ্যারের সমতুল্য।

এই ডাম্পে মোট **২১০,০৮২টি রেকর্ড** আছে এবং প্রতিটি রেকর্ড একটি **প্রশ্ন (question bank item)** নির্দেশ করে — অর্থাৎ এটি কোনো প্রশ্নবিউকের রপানি ডাম্প।

প্রতিটি লাইনে থাকা ১৫টি ফিল্ড:

| ফিল্ড | কী নির্দেশ করে |
| --- | --- |
| `p` | রেকর্ড/প্রশ্নের আইডি (সংখ্যা) |
| `q` | প্রশ্নের টেক্সট (HTML-সহ, ছবি থাকতে পারে) |
| `t` | প্রশ্নের সরল টেক্সট (HTML বাদ দেওয়া, গণিতীয় সূত্র সরলীকৃত) |
| `o` | অপশনের তালিকা — একটি অ্যারে |
| `a` | সঠিক উত্তর কোন নম্বর অপশন (১ থেকে শুরু); `o` অ্যারের যে অপশনের `c` = ১, তার সাথেই মেলে |
| `e` | ব্যাখ্যা (HTML-সহ, ছবি হতে পারে, না থাকলে `null`) |
| `et` | ব্যাখ্যার সরল টেক্সট (না থাকলে `null`) |
| `db` | উৎস ডাটাবেস/ক্যাটাগরির কোড — যেমন `Ac.QB`, `Ad.QB`, `qb5`, `EAP`, `MAP`, `JOB`, `Ex.MCQ`, `AAP` |
| `un` | বিশ্ববিদ্যালয়/বোর্ড/প্রতিষ্ঠান — যেমন `BCS`, `JU`, `RU`, `DU`, `CU`, `SUST`, `UDV`, `NSTU`, `RTN`, `BSMRSTU`, `SylaU`, `Nursing`, `Primary`, `চট্রগ্রাম বোর্ড` |
| `un2` | ইউনিট/ভাগ — যেমন `Unit-A` থেকে `Unit-F`, `Science`, `MAP`, `EAP`, `VAP`, `Diploma`, `P.Assistant`, `Preli` |
| `y` | সন (যেমন ২০১০–২০২৪) |
| `sh` | শর্ট নাম/সেট লেবেল — যেমন `Set-1`, `Set-2`, `MCQ`, `DailyM`, `WeeklyM`, `PSFM`, অথবা `খ`/`গ`/`ঘ` |
| `s` | পেপার/সিরিয়াল বা সেকশনের নাম — যেমন `P-1`, `B-1`, `M-1`, `Eng-Grm` |
| `c` | অধ্যায়/টপিক — যেমন `P-1.2`, `B-2.4`, `Voice`, `Preposition`, অথবা বাংলায় টপিকের নাম |
| `k` | কীওয়ার্ড/টপিক ট্যাগ — কখনো বাংলা টপিকের নাম (যেমন `"ভেক্টর রাশি ও এর প্রকারভেদ"`), কখনো সংখ্যা আইডি (যেমন `2984`) |

অপশন অ্যারে `o`-এর ভেতরের প্রতিটি অপশনে চারটি ফিল্ড আছে:

| ফিল্ড | কী নির্দেশ করে |
| --- | --- |
| `n` | অপশন নম্বর (১, ২, ৩, ৪, ৫) |
| `h` | অপশনের টেক্সট (HTML-সহ, ছবি হতে পারে) |
| `t` | অপশনের সরল টেক্সট |
| `c` | এই অপশনটি সঠিক কি না — সঠিক হলে `1`, নয়তো `0` |

> **লক্ষ্য করুন:** `c` ফিল্ডটি দুই জায়গায় আসে। রেকর্ডের ভেতরের (top-level) `c` মানে অধ্যায়/টপিক, কিন্তু অপশনের ভেতরের `c` মানে "এটি সঠিক উত্তর কি না"।
>
> **দুই ধরনের রেকর্ড আছে:** বেশিরভাগ রেকর্ড বাছাই করা প্রশ্ন (৪টি বা ৫টি অপশনযুক্ত)। আরও ৭,৯৯৯টি রেকর্ড লিখিত/রচনামূলক প্রশ্ন, যেগুলোর অপশনের জায়গায় শুধু `Done` ও `Skip` নামে দুটি প্লেসহোল্ডার আছে।
>
> **এনকোডিং:** ফাইলগুলো UTF-8, **কোনো BOM নেই**, এবং লাইন এন্ডিং LF (`\n`)। প্রতিটি লাইন একটি সম্পূর্ণ JSON অবজেক্ট — কোনো রেকর্ড মাঝখানে কাটা হয়নি।
>
> **একটি জানার কথা:** মূল ডাম্পের ২১০,০৮২ লাইনের মধ্যে ৬৯ লাইনে একটি বাংলা অক্ষর লাইন ব্রেকের ঠিক মাঝে ভেঙে আছে। এটি ডাম্প তৈরির সময়ের ত্রুটি, ভাগ করার কারণে হয়নি — ভাগ করার আগে ও পরে ফাইলটি বাইট-বাইট হুবহু একই ছিল।

## ৩. কেন ভাগ করা হয়েছে

GitHub-এ কোনো একটি ফাইল **১০০ MB-এর বেশি** হলে সেটি push করা যায় না — GitHub সেই ফাইলটিকে ব্লক করে দেয় এবং Git LFS ব্যবহার না করলে আপলোড হয় না।

মূল ফাইলটির নাম ছিল `database-dump-raw-full.jsonl` আর তার আকার ছিল **২২৩.৩১ MB (২৩৪,১৫৩,২৮৫ বাইট)**, যা ১০০ MB-এর সীমা ছাড়িয়ে যাচ্ছিল। তাই ফাইলটিকে **লাইন ধরে** ভেঙে ৫ MB-এর নিচে ভাগ করা হয়েছে (মোট ৪৫টি অংশ), যাতে সবগুলো অংশ GitHub-এ আরামে push করা যায় এবং প্রয়োজনে একটি অংশ নিজে নামিয়েও কাজ চালানো যায়।

লাইন ধরে ভাগ করার কারণ: JSONL-এ প্রতিটি লাইন একটি স্বাধীন JSON অবজেক্ট, তাই লাইনের শেষে কেটে ভাগ করলে কোনো রেকর্ড অর্ধেক অবস্থায় থাকে না — যা না হলে ফাইলগুলো আর পড়া যেত না।

## ৪. আবার জোড়া লাগানোর নিয়ম

### Windows (PowerShell / cmd)

`raw` ফোল্ডারের ভেতরে গিয়ে চালান:

```
cmd /c copy /b part-*.jsonl merged.jsonl
```

অথবা PowerShell-এ:

```powershell
Set-Location raw
cmd /c copy /b part-*.jsonl merged.jsonl
```

### Linux / macOS

`raw` ফোল্ডারের ভেতরে গিয়ে চালান:

```
cat part-*.jsonl > merged.jsonl
```

### যাচাই করা

```powershell
Get-FileHash merged.jsonl -Algorithm SHA256
```

সঠিক হলে হ্যাশ দেখাবে: `EF2493BFFE41D452504DD53425A89A3329A1FFDFA9A89F975F6416F4160D51BE`

### সতর্কতা

- **নামের ক্রমেই জোড়া লাগাতে হবে** — অর্থাৎ `part-001` → `part-002` → … → `part-045`। এই ক্রম ভুল হলে রেকর্ডগুলো নিজেদের মধ্যে গুলিয়ে যাবে এবং ফাইলটি আর মূল ডাম্পের সমান হবে না।
- তিন নম্বরের শূন্য (001, 002, …) দেওয়া হয়েছে ঠিক এই কারণে, যাতে অক্ষরবিন্যুস অনুসারে সাজানোর ক্রম সংখ্যা অনুসারের ক্রমের সাথে মেলে। ফাইলের নাম বদলে দেবেন না (যেমন `part-1`, `part-2`, `part-10` করবেন না) — তাহলে অক্ষরবিন্যুস অনুসারে ভুল ক্রমে জোড়া লাগবে।
- **`/b` (binary) ফ্ল্যাগটি অবশ্যই দিতে হবে।** `copy` কমান্ডে `/b` ছাড়া ফাইলটি টেক্সট হিসেবে কপি হয় এবং Windows তখন ফাইলের শেষে EOF মার্কার (Ctrl+Z) ঢুকিয়ে দিতে পারে, যা ফাইলকে নষ্ট করে দেয়।
- **টেক্সট মোডে লিখবেন না।** PowerShell-এর `Get-Content` + `Set-Content` ব্যবহার করলে নতুন লাইন বা BOM যোগ হয়ে বাংলা অক্ষর নষ্ট হতে পারে। সবসময় বাইনারি কপি ব্যবহার করুন।
- **এডিটর দিয়ে সেভ করবেন না।** Notepad, VS Code ইত্যাদি দিয়ে অংশগুলো খুলে সেভ করলে লাইন এন্ডিং বা এনকোডিং বদলে যেতে পারে।
- অংশগুলোর মাঝে **অতিরিক্ত খালি লাইন বসাবেন না** — প্রতিটি অংশ নিজেই লাইন ব্রেক দিয়ে শেষ হয়েছে, তাই সরাসরি জোড়া লাগলেই মূল ফাইলের হুবহু সমান হবে।
- জোড়া লাগানোর আগে `raw` ফোল্ডারে আগের কোনো `merged.jsonl` নামের ফাইল না আছে তা নিশ্চিত করুন, নইলে কমান্ডটি ভুলভাবে জোড়া লাগাতে পারে।
